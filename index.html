ECHA added n-Hexane and BPAF to the REACH SVHC Candidate List on Feb 4, 2026. SCIP notification deadline: Aug 4, 2026. This page proves the Air8 KB design philosophy — using one real compliance case.

Executive Summary · KB Design Philosophy

What the KB is NOT

A database of pre-made conclusions. The KB does NOT store "Turkey denim = HIGH risk, do ARP". That would be a conclusion library — not what we built.

What the KB IS

A thinking guide: at each node, what knowledge to look up, what it looks like, what triggers it. The risk conclusion is computed by the LM through the flow — not stored in the KB.

Why compliance case proves it

L1 nodes (COUNTRY-DB, CLIENT-DB) say "who is in scope". L2 web search adds "what the specific rule says". KB principles add "how to reason about it". Only at the end does the risk dimension emerge — and it can be shaped differently for different personas.

Bottom line: The KB teaches the LM where to look and how to think. The LM computes the risk. Same KB → different personas → tailored outputs.

KB Design Philosophy — Not a Conclusion Library

The KB does not store risk. It stores the knowledge map. Risk is computed through the flow.

The core design principle: The KB teaches the LM at which node to look up what knowledge, what characteristics that knowledge has, what it contains, and what triggers it. It does not pre-package risk conclusions. The LM applies reasoning to produce risk-aligned outputs — and those outputs can be shaped differently depending on the audience.

❌ KB as conclusion library (wrong)

Storing pre-made conclusions like
"Turkey denim supplier → HIGH risk → offer ARP"

This is static. If the regulation changes, the KB is wrong. If the supplier's specific situation differs, the conclusion is wrong. It doesn't scale and it doesn't teach the LM to think.

✓ KB as thinking guide (right)

Storing:
• At which node to look (COUNTRY-DB, CLIENT-DB)
• What the knowledge looks like (country EU exposure, client distribution)
• What triggers it (chemical_compliance event)

Then: LM combines with web search + principles → computes risk conclusion at runtime.

Layer 1 — KB Routing Table
Static KB nodes — tells the LM which files to consult, based on event sub-type. Does NOT contain specific CAS numbers, current rule text, or conclusions.

  • COUNTRY-DB.md — which countries are in scope, their EU exposure profile, tariff access
  • CLIENT-DB.md — how many clients per country × product × target market
  • product-eu.md — substance category guidance (solvents, coatings, resins)
  • buyer-rsl.md — how to check buyer private RSL floor vs. regulatory floor
Layer 2 — Web Resolution + Output
Dynamic resolution — KB principles + live web search against authoritative source. This is where the specific rule is fetched: CAS numbers, thresholds, deadlines, buyer RSL values.

  • KB principles — PRIN-COMPLIANCE-COST, pain points, supplier position logic
  • Live web search — ECHA candidate list, H&M/Primark RSL, WTO updates
  • Output generation — combines KB + web → risk matrix, action plan, ARP window
