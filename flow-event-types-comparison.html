Event Sub-Types & Two-Layer KB Architecture

CP0 classifies events into Event Families (e.g., EVT-REGULATION) and Functional Sub-Types (e.g., chemical_compliance). Sub-types are functional categories — not regulation names. The specific rule lives in Layer 2, fetched via web search against the KB routing that Layer 1 provides.

Executive Summary · Three architecture decisions

Fix 1 — Sub-type vocabulary

Sub-types must be functional categories, not regulation names. Use chemical_compliance instead of reach_update. Regulation names are discovered in Layer 2, not classified in CP0.

Fix 2 — Layer 1 is routing, not data

Layer 1 tells you where to look: which KB files to consult, which search queries to run. It does NOT contain specific CAS numbers, SVHC names, or current rule text.

Fix 3 — Layer 2 is KB principles + live web search

Layer 2 combines KB pain-point principles with web search against the live regulatory source (ECHA, EU Commission, WTO). This produces the DPP-style network impact output.

Bottom line: The old page showed reach_update as a subtype with CAS numbers in Layer 1. The fix: chemical_compliance as subtype, CAS numbers fetched in Layer 2 via web, output = DPP network report.

Three floors · open only what you want

CP0 assigns an Event Family and a functional sub-type. The sub-type drives Layer 1 routing. The specific regulation is resolved in Layer 2 via web search — it should never be a CP0 classification label.

Event Family Wrong sub-type (too specific) Correct sub-type (functional) Why correct
EVT-REGULATION reach_update chemical_compliance REACH has hundreds of SVHC entries. Each one cannot be a subtype. Functional category is "chemical compliance" — discover specifics in Layer 2.
EVT-REGULATION cpsc_ban_announcement product_safety CPSC is US-specific. "Product safety" covers US CPSIA, EU GPSR, UK PSTI — any product safety rule.
EVT-REGULATION eu_drones_2025 technical_standard Regulation numbers and years are too specific. "Technical standard" captures any conformity assessment update.
EVT-REGULATION upbfa_2023 flame_retardant UPBFA is one country's rule on one chemical class. "Flame retardant" captures the functional category across all jurisdictions.
EVT-TARIFF gsp_graduation preference_expiry GSP graduation is one mechanism. "Preference expiry" covers EBA, GSP+, Everything but Arms — all preferential tariff schemes.
EVT-TARIFF mtr_2025_vietnam mtr_implementation Multiple countries have MTR (Most Favoured Nation rate) changes. The sub-type captures the mechanism, not one country's calendar.
EVT-MARKET-SHIFT buyer_sourcing_shift buyer_sourcing_shift Already functional — describes the mechanism, not a specific buyer or year.
Rule: If the sub-type name is a regulation acronym, acronym + year, or CAS number — it is too specific. Rename to the functional category. The specific rule is resolved in Layer 2 via web search against the live regulatory source.

BLayer 1 — Static KB routing table (what fires, not what it says)

Layer 1 is a routing table. Given a sub-type, it tells you which KB files to consult and what kind of live search to run. It does NOT contain specific CAS numbers, current SVHC lists, or regulation text. Those are fetched in Layer 2.

CLayer 2 — Dynamic resolution (KB principles + web search)

Layer 2 combines two things: (1) the KB pain-point principles and exposure rules from Layer 1 nodes, and (2) live web search against the actual regulatory source. The specific rule — CAS numbers, SVHC names, thresholds, deadlines — is always fetched fresh from the authoritative source.

L2
Input
KB pain-point principles from L1 + web search instructions from L1 routing
L2

L2
Output
Resolved facts: specific SVHC substances added, CAS numbers, thresholds, SCIP deadlines, affected supplier countries, buyer-specific RSL floors — all from live sources.
Plus: supplier-exposure matrix, order impact tally, WIP vs. in-transit split, action plan.

CLayer 2 — Web search resolves the specific rule (dynamic)

Layer 2 executes live searches against the authoritative regulatory source. This is where n-Hexane, BPAF, CAS numbers, and thresholds appear — fetched fresh, not stored in KB.

L2
Web Search 1
Query: site:echa.europa.eu "SVHC candidate list" "n-Hexane" OR "BPAF" 2026
Result: ECHA confirms n-Hexane (CAS 110-54-3) and BPAF (CAS 1478-61-1) added to REACH SVHC Candidate List on Feb 4, 2026. Threshold: >0.1% w/w per article. SCIP notification deadline: Aug 4, 2026. Downstream supplier disclosure: 45 days from buyer request.
L2
Web Search 2
Query: H&M RSL 2026 n-Hexane BPAF restriction limit
Result: H&M Group RSL v26.1 (published Jan 2026): n-Hexane limit = 10 ppm (0.001% w/w) — significantly stricter than REACH 0.1% floor. BPAF not yet listed in H&M RSL as of Q1 2026. Primark RSL: n-Hexane not listed; monitoring only.
L2
Combine
Layer 2 now combines:
KB principles (PRIN-COMPLIANCE-COST, PP-REG-REACH-001) Web: n-Hexane CAS 110-54-3, BPAF CAS 1478-61-1, 0.1% w/w threshold, Aug 4 2026 deadline Web: H&M RSL 10 ppm n-Hexane (10× stricter than REACH) KB: COMBO-DB → Turkey denim, China woven, PK home textile exposed
This combined output feeds directly into the DPP Network Impact Report.
